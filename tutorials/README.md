## Three things this tutorial does that most of the fleet's others do not

**It runs the network from code it carries, with a PyPI backbone.** No upstream training framework is installed; the encoder's EfficientNet-B5 stages come from torchvision built with `weights=None` (the checkpoint carries their weights), and the decoders, the focuser and the change head come from the carried `modeling.py`, which also keeps two upstream quirks as they are (weights that the forward pass never uses).

**It fetches academic-use-only data and says so.** LEVIR-CD may be used for academic purposes only and its imagery is subject to Google Earth's terms; the notebook states the terms in the Prerequisites, fetches the authors' mirror at an immutable revision for that purpose, extracts exactly the pinned members and redistributes nothing.

**It evaluates on a true hold-out and adapts on the training split, and says what that means.** Roles are the dataset's own splits: the test crops were never seen by the upstream training, the bounded adaptation trains on crops of the split the model already learned from, and the notebook reads the flat result against the all-unchanged baseline rather than presenting it as an improvement.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import; its only network peers are the Hugging Face Hub (the checkpoint and the tarball at immutable revisions) and PyPI. Section 2 embeds the repository's 4 modules (`modeling.py`, `metrics.py`, `pipeline.py`, `samples.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 2-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes both entries and asserts the checkpoint's digest against the package constant; `CFNetChangePipeline.from_pretrained(weights_dir=..., report=print)` audits and converts the pickle when the safetensors file is absent, verifies it against the pinned digest, builds the vendored network and loads it strictly. The pickle is unpickled exactly once, in that conversion, through torch's weights-only loader, after the audit.
- **Stages (§4.1):** `fetch_sample_dataset` (the pinned tarball, extracted) / `load_byod_dataset` (sample acquisition) → `dataset_manifest` + `validate_dataset` refusal probes (validation, with the ceilings and a dataset digest) → roles from the dataset's splits (train / validation / test) → `pipe.evaluate` on the frozen model with the all-unchanged baseline (baseline) → `pipe.adapt` (bounded change-decoder fine-tuning) → `pipe.evaluate` on validation and test with the paired comparison (evaluation) → `pipe.predict` change maps (inference) → `pipe.save_artifact` → `CFNetChangePipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the change map is the network's `tanh` output, labelled uncalibrated; the decision rule is the upstream threshold of 0.5, and the notebook says any other threshold or post-processing is the deployment's to set.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the all-unchanged baseline is scored on the same pixels as every model number, and every metric is labelled as pixel-pooled tutorial sample-sanity evidence from 24 test crops chosen for having change, with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** roles come from the dataset's published splits, never from shuffling crops; validation loss selects the epoch and the test crops are used for nothing but the final evaluation; the notebook states that overlapping crops of one scene are near-duplicates and that real data must be split by scene; `check_split_disjoint` refuses a crop or a source pair in two splits. In BYOD mode the seeded split is by pair and the notebook says to group by scene.
- **Ceilings (VAL6):** the side range and multiple, the equal-size rule, the label values and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user pairs flow through the same validation, baseline, adaptation, evaluation, inference, export and reload cells. The expected zip layout, the label convention and the privacy and data-terms guidance are stated in the Prerequisites and in Section 4, and a sample pair is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
